# تحسينات أداء Blue Mobile — ملفات التعديل فقط

هذه الملفات هي **النسخ المعدّلة** لجعل النظام أسرع وأكثر سلاسة.
لا تخلطها مع الأصلية — استبدل الملفات الأصلية بهذه مباشرة ثم أعد التشغيل.

---

## 🔴 ما الذي كان يبطئ النظام؟

| # | المشكلة | الأثر |
|---|---------|-------|
| 1 | **استعلام لكل يوم (N+1)** في `/api/bootstrap` و `/api/days` — مع 400 يوم = **+400 استعلام متتالي** عند **كل عملية** (بيع/مصروف/جرد...) | السبب الرئيسي في البطء — كل عملية كانت تنتظر ثوانٍ |
| 2 | `loadBootstrap()` ثم `loadDashboard()` **متتاليين** (واحد تلو الآخر) | ضعف زمن التحميل بلا داعٍ |
| 3 | بعد كل عملية صغيرة كان **`renderAll()` يعيد رسم كل الشاشات الثماني** | تقطيع وتأخير واضح في الواجهة |
| 4 | **لا يوجد ضغط gzip** — صفحة 745KB + JSON بمئات الكيلوبايتات تُنقل خامًا | بطيء جدًا على الشبكات العادية/الهاتف |
| 5 | أنيميشن خلفية **بلا توقف** (`blur(110px)` متحرك) + `backdrop-filter` حتى **38px** + أنيميشن دخول **0.85 ثانية** | معالجة GPU مستمرة وإحساس بطء في السلاسة |

## ✅ التعديلات (5 ملفات)

### 1) `server/lib/ledger.js`
- أضيفت `daySummariesForApi(dayIds)` + `zeroTotals()`:
  إجماليات **كل الأيام في استعلام واحد** (لقطات الإغلاق) + **8 استعلامات متوازية** للأيام المفتوحة،
  بدل استعلام لكل يوم.

### 2) `server/routes/data.js`
- حلقة `for每个 day → daySummaryForApi` في bootstrap **استُبدلت** بنداء واحد `daySummariesForApi`.
- شكل الرد (JSON) **لم يتغير** — الواجهة تعمل كما هي.

### 3) `server/routes/days.js`
- نفس الإصلاح في قائمة الأيام `GET /api/days` (كان N+1 أيضًا).

### 4) `server/index.js`
- **gzip** للردود JSON > 1KB (بلا أي حزم إضافية — عبر `zlib` المدمج).
- الصفحة `Blue-Mobile.html` تُضغط **مرة واحدة وتبقى في الذاكرة** (‏745KB → ‏~339KB).
- `Cache-Control: no-cache` — إعادة تحقق خفيفة (304) بدل تنزيل الصفحة كاملًا كل زيارة.

### 5) `Blue-Mobile.html`
- **`reload()` متوازي**: bootstrap + dashboard معًا (`Promise.all`).
- **رسم كسول ذكي**: بعد كل عملية تُعاد رسم **الشاشة الظاهرة فقط**؛
  الشاشات الأخرى تُرسم أولما يُفتحها (`navigate` يتحقق من `viewDirty`).
- **Debounce** لبحث المخزون (‏150ms) — لا تُصفّى 3000 منتج مع كل ضغطة مفتاح.
- تحسينات CSS:
  - إيقاف أنيميشن كرات الخلفية الثابتة حاليًا (كان يعيد الرسم بلا توقف).
  - تقليل `backdrop-filter` من 38px إلى **14px كحد أقصى** (المظهر الزجاجي محفوظ).
  - انتقالات البطاقات: 0.5s → 0.25s · دخول الشاشة: 0.5s → 0.28s · ظهور المحتوى: 0.85s → 0.38s.

## 📦 طريقة التركيب

```bash
# 1) فك الضغط في مكان آمن
unzip blue-mobile-fast-fixes.zip -d /tmp/bm-fix

# 2) استبدل الملفات الأصلية (من داخل مجلد blue-mobile/)
cp /tmp/bm-fix/Blue-Mobile.html            ./Blue-Mobile.html
cp /tmp/bm-fix/server/index.js             ./server/index.js
cp /tmp/bm-fix/server/lib/ledger.js        ./server/lib/ledger.js
cp /tmp/bm-fix/server/routes/data.js       ./server/routes/data.js
cp /tmp/bm-fix/server/routes/days.js       ./server/routes/days.js

# 3) أعد التشغيل
npm start
```

> لا حاجة لتشغيل أي هجرة (migrations) — التعديلات في منطق القراءة والعرض فقط.

## 📊 النتائج المتوقعة

- **كل عملية** (بيع/إرجاع/مصروف/جرد...): من **+400 استعلام متتالي** إلى **~22 استعلامًا** معظمها متوازيعلى **مئات الملّي ثانية** بدل ثوانٍ.
- **تحميل الصفحة**: ‏745KB → ‏~339KB مع gzip (توفير ~400KB في كل زيارة).
- **بعد كل عملية**: رسم شاشة واحدة بدل ثماني شاشات → لا تقطيع.
- **الواجهة**: بلا أنيميشن خلفية مستمر، blur أخف، انتقالات أقصر → إحساس بالسلاسة.
